# Datasets

* [The adapt copy](adapt-copy.md) - `.lokf/fix-orchestra.yaml`, which `just lokf-adapt` writes from the schema so that it can sit beside LOKF's: the file this bundle validates against, and the file a release attaches as `schema-<tag>-fix-orchestra.yaml`.
* [The common module](common-module.md) - `src/fix_orchestra/schema/fix_orchestra_common.yaml`: the 13 value lists both editions share, `OrchestraMetadata` for the Dublin Core block that heads a file, and `OrchestraXmlElement` and `OrchestraXmlAttribute` for XML the XSDs leave open.
* [Where FIX's files break a rule](document-departures.md) - `tests/document_departures.yaml`: each rule a real FIX file breaks, by file and JSON pointer. FIX's two session files put groups in a category named Common, which neither defines.
* [The example data](example-data.md) - `tests/data/`: a valid example of each class, taken from the example files, three small whole files for the rule tests, a counter-example per kind of constraint, and a counter-example per rule the JSON Schema cannot state.
* [The example Orchestra files](example-files.md) - `tests/data/xml/`: four Orchestra files this project wrote, a repository and an interfaces file for each edition, with one of each kind of element the XSDs define, since no published RC3 file is valid against RC3's XSDs.
* [The example venue's order flow](example-flow.md) - A v1.0 flow from the example repository, `OrderFlow`, which carries orders from the actor Trader to the actor Venue with recoverable delivery.
* [FIX Latest EP312](fix-latest.md) - `upstream/documents/OrchestraFIXLatest.xml`: FIX Latest as of Extension Pack 312, a v1.0 Orchestra repository of 181 messages and 6,203 fields that the tests validate with the XSD and the schema and convert back unchanged.
* [The fix-orchestra LinkML schema](fix-orchestra-linkml-schema.md) - `src/fix_orchestra/schema/`: the umbrella `fix_orchestra.yaml` over `fix_orchestra_common`, `fix_orchestra_v1_0` and `fix_orchestra_v1_1`, a LinkML model of FIX Orchestra's repository and interfaces files in two editions, with four tree roots.
* [The generated artefacts](generated-artefacts.md) - `project/`, `src/fix_orchestra/datamodel/` and `docs/schema/`: what `just gen-project` and `just gen-doc` write from the schema, such as the JSON Schema, the Pydantic models and the OWL, never edited by hand.
* [The neighbours' copies](neighbour-copies.md) - `tests/neighbours/`: the schema assets of 30 released lmodel repositories, each checked against its release's `.sha256` and attestation, against which the adapt copy is held to share no class or key.
* [The rules a validator cannot state](orchestra-rules.md) - `tests/orchestra_rules.py`: the XSDs' `xs:key` and `xs:keyref` constraints and the references the specification describes, checked over a whole file, which JSON Schema cannot state.
* [The copy of FIX's files](upstream-copy.md) - `upstream/`: both editions' XSDs and licences and five of FIX's own Orchestra files, 30 files in all, each unchanged and pinned by git object hash in `scripts/upstream_pins.tsv`.
* [The v1.0 module](v1-0-module.md) - `src/fix_orchestra/schema/fix_orchestra_v1_0.yaml`: 77 classes for Orchestra v1.0's repository and interfaces XSDs, among them 5 mixins and 9 member classes, each name ending in `V10`, which the XSD converter writes.
* [The v1.1 RC3 module](v1-1-module.md) - `src/fix_orchestra/schema/fix_orchestra_v1_1.yaml`: 84 classes for Orchestra v1.1 RC3's repository and interfaces XSDs, among them 5 mixins and 9 member classes, each name ending in `V11`, which the XSD converter writes.
* [The words table](words-table.md) - `scripts/orchestra_words.yaml`: this project's own title and description for every class, key and value list the schema renders, written from what each element does and not from FIX's text.
